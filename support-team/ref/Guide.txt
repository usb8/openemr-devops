7. Compose and deploy new docker images:
    docker compose up -d --build

8. Verify that Kafka connect is running:
    curl -s http://localhost:8083/ | jq

9. Register Connector via Kafka Connect API:
    curl -i -X POST -H "Accept:application/json" -H "Content-Type:application/json" \
    --data @debezium-mysql.json http://localhost:8083/connectors
Check that it is running:
    curl -s http://localhost:8083/connectors/ | jq
And verify the status of it:
    curl -X GET http://localhost:8083/connectors/mariadb-connector/status
Verify if it receives messages
	docker exec -it kafka-1 kafka-consumer-groups.sh --bootstrap-server kafka-1:9092 --group connect-mariadb-sink --describe

10.Repeat same with jdbc:
    curl -i -X POST -H "Accept:application/json" -H "Content-Type:application/json" \
    --data @jdbc-sink.json http://localhost:8083/connectors

10. If everything is set-up correctly, you should see list of topics Kafak has:
    docker exec -it kafka-1 kafka-topics.sh --bootstrap-server kafka-1:9092 --list
Check if openemr-changes.openemr and mariadb_schema_history are there. I have many topics there

11. To see the messages itself run this command. It should return changes to the tables architecture (like creation or dropping)
    docker exec -it kafka-1 kafka-console-consumer.sh --bootstrap-server kafka-1:9092 --topic mariadb_schema_history --from-beginning
If you want to see changes for a row of data, you have to use specific table name
For example openemr-changes.openemr.test_kafka means:
topic = openemr-changes
schema = openemr
table = test_kafka
Command;
    docker exec -it kafka kafka-console-consumer.sh --bootstrap-server kafka:9092 --topic openemr-changes.openemr.test_kafka --from-beginning

It should return to you json format file
mariadb_schema_history can be replaced to any other topic you have available
but at least mariadb_schema_history should have topic available if you've had some activity on sql server

12. To check if messages were consumed by jdbc container:
    docker exec -it kafka-1 kafka-consumer-groups.sh --bootstrap-server kafka-1:9092 --group <topic_name_in_file> --describe
If CURRENT-OFFSET is "-" and LAG has values, then jdbc not processing messages
You can check the logs using:
    docker logs kafka-connect --tail=50

13. In case of problems / if you need to do changes to the json configurations;
Delete the connectors by using:
    curl -X DELETE http://localhost:8083/connectors/<connector_name>
For example:
    curl -X DELETE http://localhost:8083/connectors/mariadb-sink
    curl -X DELETE http://localhost:8083/connectors/mariadb-sink

Restart the docker:
    docker restart kafka-connect
Post again the connectors like mentioned in step 9 and 10

14. The current setup for JDBC only looks for changes in specific table
defined under parameter table.name.format
